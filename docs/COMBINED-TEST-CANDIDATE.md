## Packaging-only changes

Production C/C++/Rust source and target main CMake are retained byte-for-byte.
Host test CMake defaults use relative LVGL paths instead of a private workspace.
Two supplementary oracle-comparison tests take explicit library paths through
`PLAYING_CARDS_ORACLE_LIBRARY` and `SEED_HELPERS_ORACLE_LIBRARY`; missing libraries
remain hard failures, not skipped or substituted oracles. Their historical
oracle libraries are not part of the installed firmware and are not bundled.
The standard host gate runs real combined runtime, GUI, application-lifecycle,
extra-dice and LifeHash sources. Existing gates are retained; the runtime-lock
check is updated to the exact expanded graph, not removed. The ELF API gate adds
both conversion and passphrase exports. LifeHash vendor checksums are refreshed
to the already-installed portability fixes (initializer order and direct standard
headers), not new algorithm changes. Old vendor manifests remain historical.
Generated host executables and pixel evidence are omitted; public pixel evidence
is regenerated by tests. Supplemental registry license files are included where
provided by the published crate; see `COMBINED-RUST-LICENSES.json` and repository
notices. No firmware, logs, caches, private seed data or private paths belong in
the publication inventory.

## Build and verify

Use the pinned ESP-IDF revision with its submodules and exported target tools,
and install the pinned Rust toolchains with the nightly `rust-src` component.
These are user-local prerequisites, not actions performed automatically here.

```sh
# Host LVGL source must be the pinned 9.5.0 revision used by .github/workflows/host.yml.
LVGL_SOURCE_DIR=/path/to/lvgl bash scripts/test-host.sh
# ESP-IDF export.sh must have been sourced; no device is accessed by this command.
bash scripts/build-firmware.sh
```

Use a clean checkout for a fresh build. No historical object/archive is required.
The target recipe builds Rust from source before the ESP-IDF link and verifies
component-lock stability, target ABI, symbol ownership and image layout.
Host tests do not prove target resources or physical behavior. CI is host-only;
this publication does not represent it as a hardware gate.
